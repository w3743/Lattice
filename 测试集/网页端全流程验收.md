# 网页端全流程验收

这份验收从 `http://127.0.0.1:8000/` 开始，网页操作是主入口；后端测试只作为补充。

## 通过标准

一次完整验收必须经过：

1. 任务边界：选择端口数量，确认工作流进入端口编辑。
2. 端口与行为：分别编辑每个端口的端子、物理量、方向、领域、分析上下文和约束。
3. 元件与搜索：选择允许元件，查询已有拓扑，确认结果受元件库和端口关系约束。
4. 提交与证据：提交 PBDL，等待候选搜索、仿真、优化、约束验证和导出完成。
5. 结果核验：网页显示候选数量、验证状态，并能打开 KiCad 原理图、SPICE 网表和完整报告。

## 核心回归场景

### AC 双端口低通

- 端口数：2
- 输入端口：电压激励，1 MHz 或更低频率范围
- 输出端口：电压响应
- 行为：lowpass
- 允许元件：`R`、`C`、`opamp`
- 通过条件：出现候选，验证通过，结果含 KiCad、SPICE、JSON 三类产物

### PBDL 语法错误

在“直接编辑完整 PBDL JSON”中输入 `{`，点击“开始合成”。页面必须显示：

- 阶段：`PBDL 解析`
- 代码：`invalid_pbdl`
- 具体解析原因
- 修复建议

### 阶段能力缺口

在“规划并执行多阶段 PBDL”中提交包含 `s_parameter` 分析的需求。页面必须同时显示：

- 阶段结果为 `UNSUPPORTED`
- 阶段：`PBDL 规范`
- 代码：`capability_gap`
- 缺失能力和下一步建议
- 不得伪造候选电路或显示“设计成功”

## 错误报告契约

所有网页错误和阶段错误都应使用 `circuit_ai.error_report`，至少包含：

```json
{
  "schema": "circuit_ai.error_report",
  "schema_version": 1,
  "phase": "pbdl | ir | candidate_search | optimization | simulation | verification | export",
  "phase_label": "用户可读阶段名",
  "code": "稳定的机器可读代码",
  "severity": "warning | error",
  "message": "简洁原因",
  "detail": "可定位的细节",
  "suggestion": "用户下一步动作",
  "retryable": false,
  "cause_type": "异常类型或原因类别",
  "context": {}
}
```

阶段执行结果还必须保留 `stage_name`、`stage_index`、`status` 和 `error`。这样网页可以指出是哪一阶段、哪一个需求、哪一种能力失败，而不是只显示一个总失败。

## 复现命令

启动工作台：

```powershell
python workbench.py --host 127.0.0.1 --port 8000
```

运行网页契约和后端补充测试：

```powershell
python -m pytest -q tests/test_frontend_contract.py tests/test_webapp.py
```

浏览器验收不应被后端测试替代。每次修改 `index.html`、`app.js`、`app.css` 或 Web API 后，都要重新从页面走完至少一个成功场景和一个错误场景。

## 扩展测试集的网页验收子集

需求文件位于 `测试集/pbdl/classic/`，建议从网页端按下面顺序抽取：

| 文件 | 验收重点 | 预期 |
|---|---|---|
| `ac_rc_lowpass_1khz.json` | 双端口、元件库约束、成功导出 | 成功并出现 KiCad/SPICE/JSON |
| `ac_sensor_filter_match_10khz.json` | 两个连续频域阶段 | 两个阶段分别显示执行结果 |
| `ac_tia_output_match.json` | 电流端口跨阻加输出阻抗 | 一个阶段执行，另一个阶段显示 `capability_gap` |
| `ac_three_port_supply_adapter.json` | 三端口规划边界 | 不应在报告中伪装成完整多端口执行 |
| `future_noise_lna.json` | 噪声分析能力缺口 | `UNSUPPORTED` + 结构化错误 |
| `future_rf_sparameter_100mhz.json` | S 参数能力缺口 | `UNSUPPORTED` + `capability_gap` |

网页端测试应记录：输入文件、浏览器操作、最终阶段状态、错误代码和生成物链接；不能只记录“按钮点击成功”。
