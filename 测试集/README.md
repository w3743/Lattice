# 经典电路需求测试集

这个目录是 PBDL 的需求级回归集，不是元件参数数据库，也不是厂商参考设计或 SPICE 网表仓库。

它回答的问题是：给定一个经典电路需求，系统能否正确地：

1. 读取并规范化 PBDL；
2. 识别当前是否具备相应的分析与求解能力；
3. 对当前可支持的需求产生可执行的规划；
4. 对尚不支持的需求明确报告能力缺口，而不是伪造电路。

## 内容

- `pbdl/classic/`：101 个经典需求，覆盖滤波器、放大器、跨阻、阻抗匹配、DC/DC 电源、多阶段、多端口、振荡器、比较器、驱动、基准和 RF。
- `pbdl/baseline/`：从 `端口描述语言/examples/` 复制的 10 个既有 PBDL 基线，用来防止历史能力退化。
- `清单.json`：每个案例的领域、类别、来源分组、预期规划状态和测试层级。
- `来源.json`：公开资料与外部基准的来源清单。
- `构建测试集.py`：可重复生成上述 JSON；不下载、不复制第三方 SPICE 网表或 PDK 数据。

当前清单共 111 个样例：71 个预期可规划、39 个明确能力缺口、1 个混合阶段。
其中多端口样例标记为 `planner_boundary`，用于暴露当前执行 IR 仍是两端口适配器的边界，不把规划通过等同于多端口电路已经完成。
每条记录还带有 `validation_scope` 和 `expected_error_code`，便于后续接入网页端全流程验收。

## 当前状态的含义

`expected_planning` 描述的是当前规划器的预期行为，而不是“电路一定已经被完整设计”。

- `supported`：PBDL 可进入当前的 AC 或理想 DC 电源规划路径。
- `mixed`：同一需求中既有可执行阶段，也有明确的能力缺口。
- `unsupported`：此案例是有意保留的前沿需求，当前应报告缺少瞬态、周期稳态、S 参数、噪声、非线性、热或真实器件模型等能力。
- `mixed`：同一需求有可执行阶段和能力缺口阶段，必须允许已支持阶段完成，同时保留阶段级错误报告。

尤其要注意：`supported` 的 DC 功率案例当前由理想平均模型验证，不能视作真实开关器件、环路稳定性、热和 EMI 的工程签核。

## 外部数据集盘点

| 资源 | 与本项目的关系 | 处理方式 |
|---|---|---|
| IEEE P2427 analogue benchmark circuits | 可作为混合信号/故障仿真基准候选 | 仅登记来源；后续按其许可逐项导入 |
| AnalogGym | 模拟电路合成评测框架 | 多数任务依赖 PDK/仿真环境，保持外部引用 |
| Circuit Design Benchmarks | 需求级样例的参考来源 | 本测试集独立以 PBDL 表达，不复制其记录 |
| CircuitNet | 布局、拥塞和 IR-drop 数据 | 与当前原理图/拓扑综合层不同，暂不混入 |
| 本仓库 `data/synthetic_*.jsonl` | 训练用合成响应数据 | 与需求测试分离，不作为“经典需求真值” |

资料链接及用途见 [来源.json](来源.json)。公开资料启发了需求类别和量级；本目录的规格是为 PBDL 编写的独立测试要求，不宣称等同于这些资料中的完整电路。

## 使用

重新生成数据：

```powershell
python 测试集/构建测试集.py
```

运行回归测试：

```powershell
python -m pytest -q tests/test_classic_requirement_suite.py
```

查看全部需求的规划状态：

```powershell
python 测试集/运行测试集.py --mode plan
```

执行 4 个代表性 smoke 案例并写入 `outputs/test_suite/`：

```powershell
python 测试集/运行测试集.py --mode smoke
```
